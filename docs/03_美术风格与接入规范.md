# 亡灵老虎机 · 美术风格与接入规范（v3.1）

> 给做美术的人（或 AI）：这份文档讲**画成什么样、画多大、交什么格式、怎么接进原型**。要做哪些东西看 [02_美术资产清单](02_美术资产清单.md)，玩法看 [01_游戏完整设计文档](01_游戏完整设计文档.md)。
>
> 文中分两种语气：**「必须」= 硬约束**（不遵守会影响可玩性或者接不进去）；**「建议」= 默认方向**（可以按美术判断改，但改了请在交付说明里写清楚）。

## 2. 硬约束（必须）

### 2.1 敌人是人类，不是动物

敌人的 id（`duck`、`wolf`、`gorilla`、`elephant`、`bigcat_lion` …）是原始资料的动物编号，**本作里全部是中世纪人类军队**。按 `name`（木棒乡勇、联盾步兵、城垒卫兵、攻城战车兵、王廷重剑士 …）和 `look`（头饰、武器、副手、坐骑 / 车）画人。阶级要有视觉梯度：

| 阶级 | 数量 | 视觉 |
|---|---:|---|
| 民兵 | 11 | 农民、布衣、草帽布帽、木棒草叉木棍，体型略小（×0.78–0.95） |
| 步兵 | 16 | 皮甲、铁盔、矛盾斧，正常体型 |
| 精锐 | 29 | 板甲、徽记、披风、精良武器，有的拿火枪 / 弓 / 香炉 |
| 重装 | 8 | 披甲骑兵、独角兽骑卫、攻城槌车、投石车、攻城塔、战车 |
| 首领 | 12 | 王冠、主教冠、大披风、坐骑，体型 ×1.3–1.95 |

### 2.2 阵营一眼可分

一场首领战能有 100 多个单位混战（图 39、45）。**必须**：亡灵（冷色、骨白、发光眼、腐化感）和人类（暖色、金属、布、旗帜）在缩小到 40 像素时仍然一眼分得出。不要给人类用亡灵的发光眼和紫色，不要给亡灵用人类的金色徽记作为主色。

### 2.3 兵种主色

每个兵种的主色是**界面语义色**：列头描边、符号池色条、统计表、遗物色块、选兵种按钮、商店棺材背光都用它。新美术**必须**让这个颜色成为该兵种最显眼的颜色（衣服、袍子、发光），12 种之间靠颜色 + 轮廓区分：

| 兵种 | 主色 | 兵种 | 主色 |
|---|---|---|---|
| 饥腐行尸 zombie | `#5a9a3a` | 熬骨厨尸 chef | `#d08a40` |
| 丧尸巨人 frankendude | `#2f8f80` | 引雷尸匠 electrician | `#d8b020` |
| 唤骨法师 necromancer | `#8a45c8` | 引魂使者 alien | `#38b898` |
| 血宴伯爵 vampire | `#c0453f` | 冥火巫师 wizard | `#7a5ae0` |
| 咒布古尸 mummy | `#b8862a` | 骸骨统帅 general | `#d0602a` |
| 缚命巫妖 lich | `#3aa8d8` | 黑棺重卫 knight | `#7a7a98` |
| 白骨仆从 skeleton | `#d8d0b8` | 万能骨符 wild | `#9a4dff` |

注意几组容易混的：zombie / frankendude / alien（都偏绿）、necromancer / wizard（都偏紫）、chef / general / mummy（都偏橙）——**必须**靠轮廓区分（行尸佝偻、巨人方头高大、使者大头大眼；法师兜帽、巫师尖帽；厨尸高帽、统帅军帽、古尸绷带）。

### 2.4 显示尺寸是固定的

界面布局已经定死，图片会被程序缩放到下面的尺寸显示。画的时候**必须**保证在这个尺寸下可读：

| 资产 | 屏幕显示尺寸（1600×900 舞台） | 备注 |

| 白骨仆从 | 约 41×41 | |
| 人类步兵（体型 1） | 约 53×48 | 体型 k 倍：民兵 ×0.78–0.95、首领 ×1.3–1.95 |
| 人类骑兵 / 车（体型 1） | 约 63×49 | |
| 国王·白冠 | 约 103×94 | 最大的单位 |
| 老虎机符号 | **62×62**（在 76×76 的米色格子里） | 5×4 盘面一次看 20 个 |
| 兵种小图标 | 22–36 | 列头 28、符号池 32、卡片 36，用的是同一张符号图 |
| 老虎机道具图标 | 44×44（道具栏）/ 56×56（商店） | |

### 2.5 朝向与锚点

- **锚点**：所有战斗单位的坐标 (x, y) 在**脚底中点**；程序把图画在 `(x − 宽/2, y − 高)`，脚下再画一条影子。图的底边就是地面线，脚下不要留空白。
- **敌人**：默认朝左（面向我方）；向右移动时程序水平翻转。
- **我方**：现在的占位是**正面像，程序不翻转**。**建议**新美术做「朝右」的侧身像（面向敌人），接入时程序加一行翻转（见 §6.3）；如果坚持正面像，也可以直接用。
- 店主面向玩家（正面）；玩家化身向左 / 右走时翻转。

### 2.6 背景不能抢信息

- 战场背景：中间 y 150–716 是单位混战的区域，**必须**低对比、少细节；上方 104 像素以上可以放天空和远景。准备阶段列头在 y 104–170、熔炉在 650–950 × 600–724。
- 地图背景：节点每局随机生成，**不能**画固定的节点或道路；节点区域（x 80–1520、y 180–800）只放低对比的地貌。左上 / 右上 / 下方有信息面板（坐标见 01 号文档 §15.4）。
- 商店背景：地面上沿 y=520；商品在 y 480–680，背后的遮阳棚、墙要压暗，不要和商品抢。三家店的位置是固定的（墓园 x 110–610、仪式 760–1060、战斗道具 1210–1410），遮阳棚颜色用店铺色（墓园绿 `#2f5a35`、仪式橙 `#9a5a20`、战斗道具紫 `#4a2a7a`）。

### 2.7 动画不能拖慢操作

程序里的节奏是调过的，美术动画**必须**放得进这些时间：

| 动作 | 时长 |
|---|---|
| 拉杆转轴（每列依次停） | 0.75 + 0.26 × 列号 秒（大奖转 1.1 + 0.56 × 列号） |
| 每个阵型的展示 | 0.65 秒（×10 起 1.1 秒） |
| 符号消除 / 下落 | 0.25 秒 / 0.38 秒 |
| 士兵飞进列 | 0.55 秒 |
| 攻击间隔 | 1 / 攻速：我方 0.38 秒（引雷尸匠）到 0.83 秒（丧尸巨人、熬骨厨尸）；人类 0.63–1.43 秒 |
| 受击闪白 / 死亡淡出 | 0.12 秒 / 0.6 秒 |
| 被击飞 | 约 0.4 秒 |
| 技能连线 / 冲击圈 / 飘字 | 0.18 / 0.4 / 0.9 秒 |
| 商店按住购买 | 0.5 秒 |
| 地图军旗走一段路 | 0.52 秒 |
| 轮盘 | 4.2 秒 |

## 3. 风格方向（建议，可改）

**默认推荐：保留像素风，把像素密度提上去、统一起来。** 理由：①现有的布局、尺寸、程序特效都是按像素风调的；②同屏单位多、显示小，像素风的轮廓最清楚；③像素风可以直接用整数倍放大接入。

- **统一像素密度**：现在不同资产的「1 个美术像素 = 几个屏幕像素」不一样（兵种 2.5、敌人 2.2、符号 3.9），看起来不统一。建议：
  - 战斗单位：1 美术像素 = 2 屏幕像素 → 我方约 20×24 网格、人类步兵 24×24、骑兵 / 车 32×26、国王 48×48。
  - 符号 / 图标：1 美术像素 = 3 屏幕像素 → 符号 20×20（显示 60），道具图标 16×16（显示 48）。
  - 场景背景：1 美术像素 = 2–4 屏幕像素。
- **世界观关键词**：乱葬岗、骨头、墓碑、紫色魂火、绿色腐化 vs 麦田、风车、石桥、狮鹫堡、白塔、金色王冠；亡灵一方偏「哥特 + 黑色幽默」，人类一方偏「中世纪民俗 → 骑士传说（圆桌骑士）」。
- **老虎机**：冥界赌具 / 祭坛：深紫木柜 + 骨饰 + 铜边 + 紫色魂光；拉杆球头是红色（幸运时变金）。它是全游戏最重要的物件，值得最多的细节。
- **三章色调**：第一章暖黄麦田；第二章灰褐山地 + 墨绿松林；第三章米白圣域 + 金色光；终章王都金白。
- **不要继承**：占位图里兵种的「正面头像站姿」、程序拼装敌人千篇一律的人形模板、CSS 画的简单方框界面。这些都只是占位。

如果换成手绘 / 矢量风格，§2 的硬约束仍然成立，交付尺寸按显示尺寸的 2 倍（见 §5）。

## 4. 动画规范（建议）

现在的原型**没有帧动画**：单位只有程序做的上下浮动、受击闪白、死亡下沉、击飞抛物线。新美术建议给战斗单位做这些动作（帧数是建议值，像素风 8–12 fps）：

| 动作 | 帧数 | 循环 | 程序里怎么判断该播哪个（接入用） |
|---|---|---|---|
| idle | 2–4 | 是 | 没在移动、没在攻击 |
| move | 4–6 | 是 | 速度 `hypot(vx, vy) > 5` |
| attack | 3–4 | 否 | 刚攻击（`cd` 刚被重置）；**标出命中帧** |
| hurt | 1–2 | 否 | `flash > 0` |
| stun | 2 | 是 | `stunUntil > t` |
| airborne | 1–2 | 否 | `thrown` 不为空 |
| death | 4–6 | 否 | `dead`（0.6 秒内） |
| skill | 3–5 | 否 | 各兵种技能触发时（召唤、火球、号令、嘲讽、放电、魂光、输血、扔羹） |

- 骑兵 / 车：move 要有马腿或车轮循环。远程敌人（射程 > 60：火枪、弓、投石、香炉、圣座继承人）要有射击 / 投掷动作。
- 首领：建议额外做 1 个「号令 / 技能」动作和 1 张大号立绘（用于出场横幅和倒下特写，可选）。
- 特效（冲击圈、连线、投射物、落地特效）建议 6–10 帧序列或给出形状 / 颜色规范；颜色沿用 02 号文档 §9.1 的「来源色」。

## 5. 交付格式与命名

### 5.1 文件

- PNG，RGBA 透明底，sRGB，不要预乘 alpha。
- **像素风**：交「原始网格」尺寸（1 美术像素 = 1 文件像素），程序按整数倍 nearest-neighbor 放大；同时在说明里写建议放大倍数。
- **非像素风**：交显示尺寸的 **2 倍**（例：符号 124×124，背景 3200×1800）。
- 动画：横向排列的序列帧条（sprite strip），每帧等宽等高，脚底中点对齐；附一个同名 `.json`：

```json
{
  "frameW": 20, "frameH": 24,
  "anchor": [10, 24],
  "scale": 2,
  "anims": {
    "idle":   { "from": 0, "to": 3, "fps": 8,  "loop": true },
    "move":   { "from": 4, "to": 9, "fps": 10, "loop": true },
    "attack": { "from": 10, "to": 13, "fps": 12, "loop": false, "hitFrame": 12 },
    "death":  { "from": 14, "to": 19, "fps": 10, "loop": false }
  }
}
```

### 5.2 目录与命名

按 `assets/manifest.json` 里的 `id` 放，点换成斜杠，放在 `assets/final/` 下：

| manifest id | 文件 |
|---|---|
| `unit.zombie.battle` | `assets/final/unit/zombie/battle.png` + `battle.json` |
| `unit.zombie.symbol` | `assets/final/unit/zombie/symbol.png` |
| `enemy.wolf` | `assets/final/enemy/wolf.png` + `wolf.json` |
| `enemy.Kung_Roo` | `assets/final/enemy/Kung_Roo.png`（id 里的空格换成下划线） |
| `item.half` / `bitem.bomb` | `assets/final/item/half.png` / `assets/final/bitem/bomb.png` |
| `map.bg.ch1` / `map.node.elite` | `assets/final/map/bg/ch1.png` / `assets/final/map/node/elite.png` |
| `bg.shop.market` | `assets/final/bg/shop/market.png` |
| `npc.keeper.grave` | `assets/final/npc/keeper/grave.png` |
| `slot.cabinet` 等界面件 | `assets/final/slot/cabinet.png`（九宫格边框请在 json 里写 `slice: [上, 右, 下, 左]`） |

交付时更新 `assets/manifest.json`：给每个做完的条目加 `"final": "assets/final/..."`，没做的保持不变。

## 6. 怎么接进原型（给程序 / AI）

原型里所有占位图都是**运行时程序生成的**，替换的思路是：预加载图片，有图就用图，没有就用原来的程序生成（这样可以一部分一部分换）。

### 6.1 占位图在代码里的位置

| 资产 | 现在的生成函数 / 变量 | 替换方法 |
|---|---|---|
| 兵种战场形象 | `unitSprite(type)` → `{cv, url}` | 返回图片（或当前动画帧）的 canvas |
| 白骨仆从 | `SKEL_CV` | 同上 |
| 人类敌军 | `enemySprite(id)` → `{cv, url, k}` | 返回图片；`k` 是体型（可以改成 1，尺寸直接画在图里） |
| 符号 / 图标 | `ICON[key]`（dataURL）、`symArt(key)`、`spriteCanvas(ART[key], n)` | 把 `ICON[key]` 换成图片 URL；`symArt` 返回图片 |
| 骨头 / 骷髅 / 灵魂 / 乌鸦 | `ICON.bone / skull / soul / crow`、`BONE_CV / SKULL_CV / SOUL_CV / crowHub` | 同上 |
| 玩家化身 / 店主 | `AV_CV`、`KEEP_CV`、`keepCv(k)` | 同上 |
| 地图节点 / 背景 | `mapIcon(t, col)`、`mapBg(ci)` | 返回图片 |
| 商店 / 篝火 / 赌场背景 | `shopBg(type)` | 返回图片 |
| 战场背景 | `bg`（`paintBG` 生成） | 把图画到 `bg` 上 |
| 熔炉 / 篝火 / 轮盘 / 商品 / 价签 / 刷新物件 / 门 | `drawFurnace / drawCampFire / drawWheel / drawShopItem / drawPlaque / drawRing / drawShop` | 在这些函数里改成 `drawImage` |

### 6.2 预加载示例

```js
// 放在 <script> 开头：有正式图就用，没有就用程序占位
const FINAL = {};                                     // id → HTMLImageElement
function loadFinal(list) {                            // list = manifest.assets.filter(a => a.final)
  return Promise.all(list.map(a => new Promise(res => {
    const im = new Image(); im.onload = () => { FINAL[a.id] = im; res(); }; im.onerror = res; im.src = a.final;
  })));
}
const toCanvas = (im, scale = 1) => { const c = document.createElement('canvas'); c.width = im.width * scale; c.height = im.height * scale;
  const x = c.getContext('2d'); x.imageSmoothingEnabled = false; x.drawImage(im, 0, 0, c.width, c.height); return c; };

// 例：兵种战场形象
const _unitSprite = unitSprite;
unitSprite = type => {
  const im = FINAL['unit.' + type + '.battle'];
  if (!im) return _unitSprite(type);
  const cv = toCanvas(im, Math.max(1, Math.round(64 / im.width)));   // 放大到和占位差不多宽（占位画布 64 宽，战斗中再 ×0.62 显示）；尺寸差得多就改 battleFrame 里的缩放
  return { cv, url: cv.toDataURL() };
};
```

（`unitSprite` 是 `function` 声明，可以直接重新赋值；`ICON` 是普通对象，直接改键值。）

### 6.3 战斗单位的动画与翻转

const sp = spriteOf(u), k = (u.side === 'them' ? .55 : u.kind === 'skeleton' ? .85 : .62) * sp.k;
const w = sp.cv.width * k, h = sp.cv.height * k;
// 敌人朝右时翻转；我方现在不翻转

## 8. 给图像生成 AI 的分层提示词模板

用 AI 生成图时，**按层写提示词，不要一句话抽卡**。每次只做一类资产，先出一张定风格的样张（例如 1 个兵种 + 1 个敌人 + 1 个符号 + 1 块背景），确认后再批量。

```
【项目固定约束】
2D pixel art game asset, 1600x900 dark-fantasy comedy roguelike "Undead Slot Machine".
Thick near-black outline (#1a1014), flat shading 2–3 tones, no anti-aliasing, transparent background.
Undead side = cool colors (rot green, bone white, purple soul-fire, glowing eyes).
Human side = warm medieval colors (cloth brown, iron grey, gold, red banners). Humans are HUMANS, never animals.

【这张资产是什么】
<资产名>：<一句话说明，来自 02 号清单的「说明」列>
Must read clearly at <显示尺寸> on screen. Key color <主色> must dominate.

【构图 / 尺寸】
Single character, full body, side view facing <left/right>, feet on the bottom edge (anchor = bottom center),
<网格尺寸> pixel grid, centered, no ground, no shadow, no text.
（序列帧：<N> frames in one horizontal strip, equal frame size, same anchor.）

【风格】
<风格关键词：比如 cute-creepy undead, big head, glowing <颜色> eyes, tattered cloth …>

【负面约束】
no text, no watermark, no background scenery, no drop shadow, no blurry edges, no extra characters,
no animal features for humans, not photorealistic, no gradients across the whole sprite.
```
